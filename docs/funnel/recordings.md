## Требования к файлам

- Ролики: MP4 (H.264, без звука), 10–15 с, бесшовный цикл. Не больше 1–1,5 МБ на ролик. Рядом постер — первый кадр в WebP.
- Окна кабинета снимать светлой темой, окно 1440×900 (16:10) или 1600×900 (16:9) при масштабе 2× — потом ужать до нужной ширины.
- Телефон: Honor, `adb shell screenrecord --size 720x1608` (без `--size` он пишет 720×1280 и плющит). Статус-бар обрезать. Перед съёмкой владелец чистит шторку от личных уведомлений; тост пробного ключа вырезать.
- В кадре ничего личного и чужого: только демо-аккаунт, аккуратные названия грузов и компаний.
- Рамки окна и телефона рисует страница, в ролике их нет.

## Как снимать

- **Демо-аккаунт.** Отдельная компания грузовладельца с аккуратным названием и водитель на Honor. Грузы — по Узбекистану (граф маршрутов есть только там), названия мест крупно не показывать.
- **Езда.** Поддельная езда на Honor уже есть: `gps-lab/phone-check/replay.py CSV …` (1 Гц). Офлайн для #6: `svc wifi disable` / `svc data disable`, потом обратно. Остальные приёмы — в памяти проекта, раздел про Honor.
- **Кабинет.** Playwright + Chrome; запись видео Playwright даёт низкое качество — лучше серия скриншотов по CDP (`Page.startScreencast`) или запись экрана, затем ffmpeg.
- **Обработка.** ffmpeg: обрезка, склейка в цикл, `-c:v libx264 -crf 26..30 -pix_fmt yuv420p -an -movflags +faststart`; постер — `-frames:v 1` в WebP.

### Грузы в съёмке

Водитель может держать только один активный груз, поэтому грузы идут по очереди: доставили → диспетчер подтвердил → следующий.

| Груз | Маршрут | Для каких кадров |
|---|---|---|
| А | склад в Ташкенте → Самарканд, «Цемент М500, 22 т» | #3 (создаём его же), #4 (ссылка водителю), #1 #2 #9 (загрузка и старт), #5 (в пути), #7 (ссылка получателю) |
| Б | Ангрен → Коканд через перевал Камчик, «Стройматериалы, 18 т» | #6 («Нет данных» на перевале → маршрут целиком), #8 (стоит с … на посту) |

Время прибытия в кабинете = прямое расстояние / текущая скорость, поэтому далёкая точка разгрузки даёт часы («~3 ч 40 мин»), а не минуты.

### Езда

Своя поддельная поездка под каждый груз: строю маршрут по нашему Valhalla между точками погрузки и разгрузки (тем же графом, что рисует плановую линию в кабинете), 1 Гц, скорость 60–80 км/ч, разгон со склада, для Б — участок стоянки 20 мин. Так грузовик едет точно по синей линии, а не по городу, как в Эталон-CSV.

**Скорость — через Appium Settings** (`io.appium.settings` 8.2.1, поставлен на Honor 01.11 с согласия владельца). `replay.py` через `cmd location` скорость не передаёт, поэтому езда — `gps-lab/phone-check/gen_drive.py` (маршрут из Valhalla → CSV 1 Гц с фазами `d<мин>` / `s<мин>`) + `replay_appium.py` (каждую секунду `am start-foreground-service … LocationService --es speed … --es bearing …`). Готовые поездки: `drives/a.csv` (Сергели → Самарканд, 4+15 мин), `drives/b.csv` (Ангрен → Коканд по A373 «Камчик»: 5 езды, 7 офлайн, 4 езды, 20 стоянки).

**Репетиция 01.11, 04:20–04:41** (груз YL-1043, потом удалён):
- скорость и время прибытия в кабинете есть («34 км/ч», «~2 ч 34 мин»);
- офлайн: через 5 мин бейдж «Нет данных с 04:24», после включения сети очередь за 7 мин пришла одной пачкой;
- стоянка: «Стоит с 04:34» через ~5 мин (сервер решает по геометрии; библиотека сама в «стоим» не перешла, точки шли и на стоянке);

Поэтому на всю съёмку: Wi-Fi выключен, фоновое сканирование Wi-Fi и Bluetooth выключено (`settings put global wifi_scan_always_enabled 0`, `ble_scan_always_enabled 0`; было 1 и 1 — вернуть после съёмки), интернет — мобильный;

### Порядок съёмки (одна сессия ~1,5–2 ч с телефоном)

1. **#3 Создать груз А.** В форме вставляем ссылку из 2GIS (полная ссылка из адресной строки браузера, с `?m=`), маршрут и км появляются. Кадр — скриншот формы.
2. **#4 Ссылка водителю.** В шаге «Назначение» → вкладка приглашения → ссылка → отправляем в Telegram. Кадр — пузырь сообщения со ссылкой, без имён и аватаров.
3. **Водитель принимает груз А** на Honor (по ссылке «Войти и принять» или из списка). Не снимаем.
4. **«Начать забор»** — груз в статусе «Идёт загрузка», грузовик стоит у склада.
5. **#1 + #2 главная сцена** — пишем одновременно кабинет и телефон:
   водитель нажимает «Груз загружен» → снимает накладную → в кабинете статус «Загружен», фото в хронологии, кольцо-отметка на карте → водитель нажимает «Начать перевозку» (#9 из этого же дубля) → «В пути», грузовик трогается, появляются скорость и время прибытия.
   Монтаж: камеру ускоряем/режем, цикл 12–15 с, оба ролика по одним меткам времени.
6. **#5 В пути.** Через 3–4 мин езды — скриншот карточки: карта, скорость, время прибытия.
7. **#7 Ссылка получателю.** «Поделиться» → ссылка → открываем в Playwright с экраном телефона 390×844 (масштаб 3×), листаем. Запись без рамки.
8. Груз А: «Начать разгрузку» → «Подтвердить доставку» на телефоне, диспетчер подтверждает. Не снимаем.
9. **Груз Б**: принять → загрузка → «Начать перевозку» (быстро, не снимаем) → 5 мин езды.
10. **#6 Без интернета.** `svc data disable` + `svc wifi disable`, едем ещё 7 мин. Через 5 мин тишины в кабинете бейдж «Нет данных с HH:MM». Включаем сеть → пачка уходит → хвост дорисовывается до грузовика. Пишем кабинет всё время, в монтаже ожидание режем.
11. **#8 Простой.** Ещё 3–5 мин езды → стоянка. Через ~5 мин бейдж «Стоит с HH:MM», в подсказке «уже N мин». Пишем короткие куски на 6-й, 12-й, 20-й минуте → склейка, где минуты идут.
12. Груз Б доводим до подтверждения, чтобы у водителя не висел активный груз.

## Версия 2 (сессия 4а, 01.11): постер = кадр 0 = крупный план

После вёрстки сессий 1–4 оказалось, что в статике пять окон кабинета одинаковые, а ключевой элемент каждого — несколько пикселей. Перерендерено из тех же исходников (`recordings/raw/`, вне git), без пересъёмки: `tools/render_zoom.sh` v2 + `zoom.py --ease snap`.

- **Принцип:** ролик начинается и заканчивается наездом на свой главный элемент, поэтому постер (кадр 0) и последний кадр совпадают — цикл перезапускается без скачка, а статичный постер уже рассказывает историю. Переход — 0,45 с, квартичный ease-out (рывок и мягкая посадка), не плавный smoothstep: глаз сразу идёт туда, куда прыгнула камера.
- **Старт/финиш по роликам:** `01` — шапка карточки ×2,2 («Цемент M500 · Идёт загрузка · Стоит с 07:11 · 51 %»), внутри: общий план → шапка перед «Загружен» (8,0 с) → фото в истории → общий план → шапка перед «В пути» (13,5 с) → скорость и грузовик → шапка. `06` — шапка «Нет данных с 06:18» + замерший грузовик ×1,8 → карта ×1,3 без меню (путь появляется на ~8 с) → шапка перед «В пути» (14,5 с). `08` — попап «Стоит · уже 6 → 12 мин» ×1,9 → карта со стоящим грузовиком ×1,3 → попап. `07` — шапка с бейджами ×1,3 → весь экран → шапка. `02` без изменений. Длины прежние, пара `01`+`02` синхронна.
- **`09`** — только верхние 660 px экрана (шапка + карточка с кнопкой), 720×660; на странице телефон поднимается из нижнего края секции и срезан им — пустой список «Нет ожидающих грузов» в кадр не попадает. Пересъёмка с несколькими грузами — вместе с uz/en.
- **`04`** — 720×1528, Telegram в светлой теме, чат с водителем: входящее «Доброе утро! Какой груз сегодня?» и исходящее со ссылкой и превью. **Это реплика (`recordings/telegram.html` → `tools/shot-telegram.mjs`), не скриншот:** настоящий кадр был снят в «Избранном» с фиолетовой темой владельца и выбивался со страницы; Telegram Web в Chrome машины был без логина. Текст ссылки и превью — настоящие. При желании заменить на реальный скриншот (светлая тема, чат с водителем, 1080×2412 → 720×1528), файл и имя те же.
- **`03`, `05`** без изменений: ни на одном стилле нет момента вставки ссылки 2GIS (везде уже распознанный адрес), модалка создания груза и так 16:10.
- **Вес:** `01` 1,35 МБ (crf 31; при crf 28 было 1,8 МБ, разницы на крупном плане не видно), `06` 582 КБ, `07` 420 КБ, `08` 482 КБ, `09` 49 КБ; постеры 16–60 КБ (постер первого экрана 50 КБ против 88 КБ в v1).
- **Проверка:** первый/последний кадр SSIM 0,90–0,99 (меньше единицы только из-за сменившегося статуса и сдвинувшейся карты — рамка та же); лента из 9 постеров при 560 px читается без текста; пара первого экрана синхронна; горизонтальной прокрутки нет.
